# COGS SLOB Dashboard — Data Pipeline

## What this is

A single-file HTML dashboard (`cogs_dashboard.html`) with a **SLOB** section that has a SBU
selector for **AAFL**, **HRML**, and **FAL (Fariq Agro)**. Each view shows RM/PM SLOB value +
item-count pies, KPIs, and a drill-down table. The dashboard is fed by generated JS data files
that declare global variables:

- `slob_aafl.js`  -> global `SLOB_AAFL`  (generated by `fetch_slob_aafl.js`, `LIKE '%Agro Feed%'`)
- `slob_hrml.js`  -> global `SLOB_HRML`  (generated by `fetch_slob_hrml.js`, `LIKE '%Hashem%'`)
- `slob_fal.js`   -> global `SLOB_FAL`   (generated by `fetch_slob_fal.js`, `LIKE '%Fariq Agro%'`)

All three are loaded via `<script src>` tags near the bottom of `cogs_dashboard.html` and
registered in `SLOB_SBUS = ['AAFL','HRML','FAL']`.

## Data shapes (must stay in sync with the renderers)

AAFL / FAL — keyed by period (statement supports multiple months):

```js
const SLOB_AAFL = {
  sbu: 'AAFL', sbuName: 'AAFL Akij Agro Feed',
  source: 'DataMart.inv.tblInventoryStatement', window: '6-mo trailing',
  periods: {
    '2026-08': {
      values: {
        RM:     { total: <Cr>, slob: <Cr>, pct: <number> },
        PM:     { total: <Cr>, slob: <Cr>, pct: <number> },
        Other:  { total: <Cr>, slob: <Cr>, pct: <number> }, // present for FAL; optional for AAFL
        totalInv: <Cr>, slobTotal: <Cr>
      },
      counts: { rmItems, rmSlob, pmItems, pmSlob, otherItems, otherSlob, totalItems, totalSlob },
      items:  [ { item, itemCode:<str>, type:'RM'|'PM'|'Other', closingValue:<BDT>, neg6:<int>, zeroCons:<bool> }, ... ] // itemCode from itm.tblItemArc latest active mapping (may be '')
    },
    '2026-07': { /* same shape */ }
  }
};
// SLOB_FAL has identical shape, sbu='FAL', sbuName='Fariq Agro Ltd.'
```

HRML — legacy flat (single window) OR periodised if upgraded:

```js
const SLOB_HRML = {
  sbu:'HRML', sbuName:'HRML Hashem Rice Mills',
  source:'DataMart.inv.tblInventoryStatement', window:'2026-03-01 to 2026-08-22',
  // flat case:
  values: { RM:{total,slob,pct}, PM:{total,slob,pct}, Other:{...}, totalInv, slobTotal },
  counts: { rmItems, rmSlob, pmItems, pmSlob, otherItems, otherSlob, totalItems, totalSlob },
  items:  [ { item, itemCode, type, closingValue, neg6, zeroCons }, ... ] // itemCode from same lookup
  // periodised case: { periods:{'2026-08':{values,counts,items}, ...} } same as AAFL/FAL
};
```

The renderers are `renderSlobAAFL(type, zero, search, sort)`, `renderSlobFAL(type, zero, search, sort)` and
`renderSlobHRML(type, zero, search, sort)` (defined in `cogs_dashboard.html`), dispatched by
`renderSlob()` from `slobSbuFilter` + `slobPeriodFilter` + `slobTypeFilter` + `slobZeroFilter` + `slobSortFilter`.
Pies are sized by **value**; the caption and legend carry **both value and item count**.
Filters: `type` = 'all'|'RM'|'PM'|'Other', `zero` = 'all'|'slob', `search` matches `item` OR `itemCode` (case-insensitive), `sort` = 'value_desc' (default, highest SLOB value first) | 'value_asc' | 'alpha'. Table now shows columns `# | Item Code | Item | Type | Closing Value | 6-mo Consumed? | Flag`.

## AAFL / FAL methodology (authoritative value source = DataMart statement)

Scripts: `fetch_slob_aafl.js` (`LIKE '%Agro Feed%'`) and `fetch_slob_fal.js` (`LIKE '%Fariq Agro%'`).
Run with: `node fetch_slob_aafl.js` / `node fetch_slob_fal.js`.

1. **Closing value per item** = `ClosingStock * AvgRate` from the latest snapshot of
   `DataMart.inv.tblInventoryStatement` for the target period (window `ROW_NUMBER() OVER
   (PARTITION BY [Business Unit], strItemName, Warehouse ORDER BY dteTransactionDate DESC)` where
   `dteTransactionDate <= asOf`, then `rn=1`).
2. **RM vs PM vs Other split** is keyword-based on `strItemName.toLowerCase()`:
   - **PM first** (checked before RM — many rice bags contain variety names): `pack|bag|carton|label|pouch|wrapper|sack|sticker|tin|can|cap|liner|bottle|film|tape|strap|jute|gunny|pp |bopp|laminated|hessian|poly|woven|sieve|sensor|cable|bar|sheet`
   - **RM**: `raw|cement|steel|coal|grain|pulse|feed|rice|flour|meal|soy|maize|corn|husk|bran|seed|oil|salt|sugar|wheat|paddy|dal|chinig|katari|najir|miniket|paijam|shorna|parija|hybrid|atop|bogi|mota|chikon|kalijira|sona|samba|bora|godown|moti` — includes rice variety tokens so finished rice (Chinigura, Katari, etc.) maps to RM for rice mills.
   - **Other**: everything else (engineering spares, etc.). FAL's Other is small (~0.6–0.7 Cr) after the variety fix; AAFL previously had larger Other.
3. **SLOB flag** = an item with **zero negative-quantity transactions** in the trailing 6-month window
   of `tblInventoryStatement` (`IssueOrreceivedQty < 0` and `dteTransactionDate BETWEEN DATEADD(month,-6,asOf) AND asOf`). `neg6` = count of those txns; `zeroCons = (neg6 === 0)`.
4. **Totals** = sum of closing values; `slob` = sum where `zeroCons`; `pct` = slob/total.

Current statement-based totals (Aug 2026):
- AAFL: RM 94.5 Cr / SLOB 0.77, PM 5.9 / 1.46, All 138–147 Cr
- FAL:  RM 48.7 / 12.78 (26%), PM 1.96 / 0.39 (20%), Other 0.68 / 0.45, All 51.39 / 13.62
- Statement totals are higher than legacy finance CSV totals (~100 Cr for AAFL) because the statement includes more items / different cutoff. This is expected.

## HRML methodology (authoritative value source = DataMart statement; legacy CSV flat still supported)

- Current `slob_hrml.js` is also sourced from `DataMart.inv.tblInventoryStatement` (same closing-value + 6-mo neg-qty logic) but emitted as a **flat** single-window file (`values/counts/items` + `window`). The dashboard detects this and shows a single `6-mo` period option.
- Legacy path (finance SLOB CSV + WMS shop-floor consumption) is still documented for reference but no longer used for generation.
- SLOB flag = same 6-mo negative-qty definition as AAFL/FAL.

## When editing

- After changing the data shape in a fetch script, update the matching `renderSlob*` function so
  field names line up (e.g. `P.values.RM.total`, `P.counts.rmSlob`, `P.items`).
- Keep `slobRange` text accurate about the data source (statement).
- Period selector is populated from `Object.keys(SLOB_<SBU>.periods)` for AAFL/FAL (periodised) and falls back to a single `6-mo` option for legacy flat HRML.
- To add a new SBU: duplicate `fetch_slob_fal.js` with a new `BUNAME` LIKE pattern, tweak `isRM/isPM` keywords if needed, generate `slob_<code>.js`, add `SLOB_<CODE>` to `SLOB_SBUS`, extend `populateSlobPeriods` / `renderSlob` / `exportSlobCSV` and the `labels` map in `initSlob`, and add a `<script src="slob_<code>.js">` tag.

## Adding a new SBU — checklist (used for FAL)

1. Create `fetch_slob_<code>.js` (copy `fetch_slob_fal.js`, change `BUNAME` LIKE and `sbu/sbuName` in output).
2. `node fetch_slob_<code>.js` -> generates `slob_<code>.js` with `{sbu, sbuName, source, window, periods}`.
3. Add `<script src="slob_<code>.js"></script>` to `cogs_dashboard.html`.
4. Add code to `SLOB_SBUS`, `initSlob` labels, `populateSlobPeriods`, `renderSlob` dispatcher, add `renderSlob<CODE>()` (copy `renderSlobFAL`), and extend `exportSlobCSV`.


## Gotchas

- `mssql` must be installed and the machine must reach DataMart; connection config is hardcoded in
  each `fetch_slob_*.js` (`203.202.241.211`, user `mcp_user`).
- Large `tblInventoryStatement` window queries can be slow — keep the 6-month window and the per-item `ROW_NUMBER()` filter. `fetch_slob_fal.js` prioritises `isPM` before `isRM` so bags with rice names (e.g. `PPW Bag Katari…`) classify as PM.
- Fariq Agro data starts only on 2025-11-24, so any period before that has a shorter trailing window; SLOB for early periods may be overstated.
- Do NOT mix value sources: AAFL/FAL/HRML all use the statement now. Legacy CSV flat for HRML is only a fallback.
